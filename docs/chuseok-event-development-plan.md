# MetDash 추석 이벤트 개발 페이즈 문서

상태: 구현 완료 / 실게임 수동 검증 대기
확정일: 2026-09-21
구현일: 2026-09-21
이벤트명: **한가위 달빛 축제**

## 1. 확정된 경험

1. 이벤트 기간에는 기존 코인 외형을 송편으로 교체한다.
2. 코인의 가치, 콤보, 자석 상호작용, 미션 집계와 저장 방식은 바꾸지 않는다.
3. 기존 **다이아몬드 3개 룰렛**은 현재 규칙 그대로 유지한다.
4. 희귀 픽업 **달토끼 보름달**을 별도로 추가한다.
5. 보름달은 일반 주행으로는 먹을 수 없는 높이에 두고, 점프 타이밍을 맞춰 획득하게 한다.
6. 보름달 획득 직후 레인보우 효과와 아래 안내를 보여 준다.

   `🌈 추석 이벤트 추가 효과! 보름달 룰렛이 열렸어요`

7. 보름달 룰렛은 `꽝`, `×10`, `×12`, `×15`, `×20`, `×25`, `×30`으로 구성한다.
8. 타이틀 화면에는 `🌕 한가위 달빛 축제` 시즌 배지를 추가한다.
9. 트랙에는 한지등과 청사초롱 장식을 추가한다.
10. 보름달에는 달토끼 무늬를 사용한다.

## 2. 보름달 룰렛 밸런스

### 2.1 확정 테이블

| 결과 | 확률 | 지속 시간 | 배율×시간 |
| --- | ---: | ---: | ---: |
| 꽝 | 15% | 효과 없음 | 0 |
| ×10 | 30% | 15초 | 150 |
| ×12 | 22% | 14초 | 168 |
| ×15 | 15% | 13초 | 195 |
| ×20 | 10% | 12초 | 240 |
| ×25 | 5% | 11초 | 275 |
| ×30 | 3% | 10초 | 300 |

### 2.2 재계산 결과

- 당첨 확률: **85%**
- 꽝 확률: **15%**
- 룰렛 1회당 기대 배율: **×12.04**
- 당첨된 경우 평균 지속 시간: **약 13.62초**
- 룰렛 1회당 기대 `배율×시간`: **157.96**
- 현재 다이아 룰렛의 기대 `배율×시간`: **44.465**
- 따라서 보름달 룰렛은 현재 룰렛보다 이 지표상 **약 3.55배 강하다.** 희귀 출현, 어려운 점프 획득, 한 판 최대 2회 제한으로 이 차이를 제어한다.

`배율×시간`은 실제 획득 점수가 아니라 룰렛끼리 비교하기 위한 대리 지표다. 실제 점수는 해당 시간에 성공한 점프·슬라이드·지붕·마운트 수에 따라 달라진다.

### 2.3 점수 적용 규칙

- 보름달 배율은 기존 룰렛처럼 **플레이로 만든 행동 점수에만** 적용한다.
- 생존 시간 점수, 송편/코인 수입, 미션 보상에는 적용하지 않는다.
- 다이아 룰렛과 보름달 룰렛은 같은 `slotMultiplier` 채널을 사용한다.
- 두 룰렛 배율은 서로 곱하지 않는다. `×10 × ×30 = ×300`은 금지한다.
- 새 당첨 결과는 기존 룰렛 효과를 교체한다.
- `꽝`은 현재 적용 중인 배율과 남은 시간을 지우지 않는다.
- 이후 다이아 룰렛에서 나쁜 결과가 나오면 현재 규칙대로 보름달 배율도 교체될 수 있다.

## 4. 게임플레이 상세 사양

### 4.1 송편

- 이벤트 활성 중 `makeCoin()`의 시각 표현만 송편 텍스처 기반 메시로 교체한다.
- 충돌체와 `SPEC.coin`은 그대로 둔다.
- 기존 회전 애니메이션을 유지하되, 카메라에서 이미지가 사라지지 않도록 양면 머티리얼 또는 교차 평면을 사용한다.
- 텍스처 로딩 실패 시 기존 금색 코인 메시로 폴백한다.
- 자석, 제트팩 하늘 코인, 코인 러시, 장애물 위 코인도 모두 같은 송편 외형을 사용한다.
- UI의 재화 명칭은 혼란 방지를 위해 `코인`을 유지한다. 이벤트 안내에서만 `송편 코인`으로 설명한다.

### 4.2 달토끼 보름달

- 새 엔티티 타입: `chuseokMoon`
- 성격: 비치명적 시즌 토큰, 자석 대상 아님
- 권장 중심 높이: **4.1m**
- 일반 점프 정점은 약 2.98m이며 플레이어 중심 높이와 픽업 도달 범위를 합치면 4.1m 보름달은 점프 중상단 구간에서만 획득할 수 있다.
- 슈퍼 스니커즈의 넓은 일반 보상 획득 범위를 그대로 적용하지 않는다. 보름달은 기본 픽업 도달 범위를 사용하고, 스니커즈는 더 높은 점프로만 도움을 준다.
- 제트팩 활성 중에는 보름달 패턴을 배치하지 않고 다음 가능한 일반 패턴까지 연기한다.
- 천장 구간, 튜토리얼, 섹션 이벤트 도중에는 배치하지 않는다.

### 4.3 보름달 패턴

보름달 레인에는 송편이 `낮음 → 중간 → 높음 → 보름달`로 이어지는 상승 아크를 둔다. 플레이어가 이미지의 깊이를 읽기 어려운 점을 고려해 높이 차이를 크게 하고, 보름달 앞 송편 간격은 현재 속도에서 점프 입력 시점을 알려 주도록 테스트한다.

인접 레인에는 지상 송편 라인을 둔다. 따라서 플레이어는 다음 중 하나를 선택한다.

- 레인을 옮기고 점프해 보름달 룰렛을 노린다.
- 안전한 지상 송편 라인을 유지한다.

보름달 패턴 자체에는 치명 장애물을 넣지 않는다. 어려움은 레인 선택과 점프 타이밍에서 만들고, 희귀 보상을 위해 목숨까지 거는 구조는 피한다.

### 4.4 출현 규칙

- 한 판 최대 출현: **2회**
- 첫 출현 가능 시점: **40초 이후**
- 두 번째 출현: 첫 출현 뒤 **55~70초** 사이
- 타이틀 화면 데모에는 출현하지 않는다.
- 이벤트 비활성 중에는 생성, 카운터, 룰렛 코드가 모두 동작하지 않는다.
- 다이아몬드, 파워업, 까마귀 알과 같은 레이아웃에 겹치지 않는다.
- 정해진 시점에 제트팩이나 섹션 이벤트가 겹치면 기회를 버리지 않고 뒤로 연기한다.

## 5. 획득 연출과 룰렛 UI

### 5.1 레인보우 획득 효과

- 보름달 위치에서 빨강, 주황, 노랑, 초록, 파랑, 보라 파티클을 짧은 간격으로 방출한다.
- 기존 `ParticleField`의 단일 드로우콜 구조를 유지한다.
- 화면 가장자리에 0.8~1.0초짜리 무지개 그라데이션 플래시를 추가한다.
- 카메라 FOV 펀치는 기존 질주보다 약하게 적용한다.
- 전용 파워업 사운드와 짧은 진동을 사용한다.
- `prefers-reduced-motion`에서는 화면 플래시와 확대 애니메이션을 줄이고 색상 변화만 남긴다.

### 5.2 보름달 룰렛

- 기존 `showSlots()`를 재사용 가능한 룰렛 화면으로 일반화한다.
- 제목: `🌕 보름달 룰렛`
- 색상: 금색 테두리와 무지개 포인터
- 꽝 문구: `🌙 꽝 · 다음 보름달을 노려보세요!`
- 당첨 문구 예시: `🌕 점수 ×30 · 10초`
- 이벤트 룰렛도 실행 중에는 게임 시뮬레이션과 타이머를 멈춘다.
- 다이아 룰렛과 보름달 룰렛이 같은 프레임에 예약되면 획득 순서대로 큐에 넣어 둘 다 실행한다. 한쪽 결과가 유실되면 안 된다.

## 6. 시즌 배지와 트랙 장식

### 6.1 시즌 배지

- 기존 `SEASON N` 배지는 유지한다.
- 그 옆에 별도 배지 `🌕 한가위 달빛 축제`를 추가한다.
- 이벤트 비활성 중에는 DOM에서 숨긴다.
- 320px 모바일에서 제목과 두 배지가 한 줄에 억지로 눌리지 않도록 줄바꿈을 허용한다.

### 6.2 장식

- 월드 세그먼트 재활용 구조에 한지등과 청사초롱 그룹을 포함한다.
- 트랙 충돌 영역 밖에만 배치한다.
- 야간에는 약한 emissive를 사용하고, 주간에도 형태가 사라지지 않게 기본색을 유지한다.
- 장식은 그림자를 만들지 않는다.
- 저화질 단계에서는 개수를 절반으로 줄이고, 최저화질에서는 emissive 장식만 남긴다.
- 장식은 픽업과 혼동되지 않도록 보름달보다 작고 채도를 낮춘다.

## 8. 리더보드와 시즌 공정성

보름달 룰렛은 최대 배율을 `×10`에서 `×30`으로 올리므로 기존 시즌 점수와 직접 비교하면 이벤트 기간 플레이어가 유리하다.

- 이벤트 시작은 새 점수 규칙 시즌의 시작으로 취급한다.
- 이벤트 종료 후 일반 규칙으로 돌아갈 때도 새 시즌 경계를 둔다.
- 클라이언트와 Convex가 동일한 시즌 경계와 최대 배율을 공유해야 한다.
- `MAX_MULTIPLIER`는 콤보 × 구간 × 룰렛(최대 30) × 캐릭터 보너스의 곱으로 계산한다.
- 생존 시간 점수에는 룰렛이 적용되지 않는 기존 불변식을 유지한다.
- 이벤트 시작일과 종료일은 배포 전에 KST 기준으로 확정한다.

## 9. 개발 페이즈

### Phase 1 — 순수 규칙과 테스트

- `src/chuseok.js`에 이벤트 테이블과 가중치 추첨 구현
- 확률 합 100, 모든 페이스 도달 가능, 최대 배율 30 테스트
- 꽝이 기존 배율을 지우지 않는 테스트
- 두 룰렛이 곱연산하지 않는 테스트
- 기록 검증 최대치 갱신 테스트

완료 조건: Three.js와 DOM 없이 모든 이벤트 규칙을 단위 테스트할 수 있다.

### Phase 2 — 에셋과 엔티티

- 송편 텍스처 프리로드와 기존 코인 폴백
- 보름달 엔티티, 회전·부유·발광 애니메이션
- 알파 가장자리, 원거리 시인성, 터널/야간 시인성 확인

완료 조건: 이벤트 ON/OFF에 따라 코인/송편이 바뀌고 텍스처 실패 시 게임이 깨지지 않는다.

### Phase 3 — 패턴과 획득 난이도

- 보름달 상승 아크 패턴 구현
- 출현 제한과 연기 규칙 구현
- 일반 점프 성공, 무점프 실패, 제트팩 중 배치 연기 테스트
- 최대 속도에서 입력 가능 시간이 충분한지 실측

완료 조건: 보름달은 점프 없이는 획득되지 않고, 정상 점프로 반복 재현 가능하다.

### Phase 4 — 룰렛과 연출

- 기존 룰렛 UI 일반화
- 보름달 룰렛 큐 및 정산 구현
- 레인보우 파티클·화면 플래시·사운드·진동 구현
- 모션 감소 환경 처리

완료 조건: 보름달을 먹으면 연출 → 안내 → 룰렛 → 정확한 시간제 배율 → 주행 복귀가 한 흐름으로 동작한다.

### Phase 5 — 시즌 외형

- 한가위 배지 추가
- 한지등·청사초롱 장식 추가
- 화질별 밀도와 모바일 레이아웃 적용

완료 조건: 320px~1280px에서 배지와 장식이 HUD, 장애물, 픽업을 가리지 않는다.

### Phase 6 — 온라인 검증과 릴리스

- 시즌 경계와 서버 점수 검증 배포
- 전체 단위 테스트, 빌드, UI 검사, E2E 실행
- 실제 브라우저에서 10회 이상 보름달 획득 플레이테스트
- 이벤트 OFF 폴백 테스트
- 변경 로그와 README 이벤트 설명 추가

완료 조건: 클라이언트가 허용하는 최고 기록을 서버도 허용하고, 이벤트 종료 후 일반 모드가 코드 삭제 없이 복구된다.

## 10. 필수 테스트 목록

- 송편은 기존 코인과 같은 수입과 미션 카운트를 준다.
- 자석은 송편을 끌지만 보름달은 끌지 않는다.
- 보름달은 땅에서 달리기만 해서는 획득되지 않는다.
- 일반 점프로 보름달을 획득할 수 있다.
- 보름달은 한 판에 세 번 이상 나오지 않는다.
- 섹션 이벤트와 제트팩 때문에 밀린 보름달은 이후에 다시 나온다.
- 꽝은 현재 배율과 타이머를 변경하지 않는다.
- `×30`은 정확히 10초 뒤 종료된다.
- 다이아 `×10`과 보름달 `×30`은 `×300`이 되지 않는다.
- 룰렛 중 게임 시간, 파워업 시간, 장애물 이동이 멈춘다.
- 동시에 예약된 두 룰렛이 모두 정산된다.
- 서버 검증은 합법적인 `×30` 플레이를 거절하지 않는다.
- 서버 검증은 새 최대치를 넘는 조작 기록을 거절한다.
- 모션 감소 설정에서 강한 화면 확대가 발생하지 않는다.
- 이벤트 OFF에서는 기존 코인, 다이아 룰렛, 타이틀, 점수 검증이 기존과 동일하다.

## 11. 릴리스 전 수동 확인

- 송편이 멀리서 장애물이나 까마귀 알로 보이지 않는가?
- 보름달의 달토끼가 모바일에서도 읽히는가?
- 보름달 높이가 어렵지만 억울하지 않은가?
- `×30 · 10초`가 충분히 체감되는가?
- 꽝 15%가 어려운 획득 뒤 과도하게 허탈하지 않은가?
- 레인보우 플래시가 장애물 판독을 가리지 않는가?
- 장식이 픽업처럼 보여 불필요한 레인 이동을 유발하지 않는가?
- 이벤트 룰렛이 너무 잦아 주행 흐름을 자주 끊지 않는가?

플레이테스트에서 조정할 때는 배율이나 지속 시간보다 **출현 빈도**를 먼저 조정한다. 이미 획득 난이도와 꽝 확률을 통과한 보상의 체감을 다시 줄이는 것보다, 특별한 순간이 얼마나 자주 오는지를 조절하는 편이 이벤트의 약속을 지키기 쉽다.
